# Green Pavlodar — AI-ассистент для озеленения города

Прототип по ТЗ акимата «AI-ассистент для анализа AI-карты и подбора решений по озеленению» (хакатон 28.10–01.11.2026). Работает на открытых данных OpenStreetMap для центра Павлодара. Слои организатора подключаются через импорт.

## Запуск

### Приживаемость: синтетическая ML-модель

`npm --prefix apps/web run train:survival` воспроизводит логистическую регрессию на 12 000 синтетических посадок (seed 20261029; обучение 80%, проверка 20%). `npm --prefix apps/web run check:survival` проверяет метрики, воспроизводимость и поведение при засолении/поливе. Коэффициенты, ROC-AUC, Brier и калибровка по десяти корзинам сохранены в `apps/web/src/shared/analytics/survivalModel.json`.

**Модель учится на синтетике, построенной из экспертных правил. ROC-AUC показывает качество на синтетике, а не на реальных посадках Павлодара.** В карточке и отчёте доступны метод, ограничения и сравнение с прежними правилами. Полная методика: [docs/survival-model.md](docs/survival-model.md).

Одной командой (нужен Docker):

```bash
docker compose up --build
```

Откройте http://localhost:8080. Поднимаются два контейнера: **web** (nginx со сборкой интерфейса, проксирует `/api` на сервер) и **server** (`apps/server`, Node 24, SQLite). База и фото лежат в томе `gp-data` и переживают перезапуск.

- По умолчанию веб собран с тестовым источником в браузере (`DATA_SOURCE=mock`) — это запасной режим на защите. Настоящий сервер на том же адресе: http://localhost:8080/?source=api
- Пароль демо-аккаунтов задаётся в `apps/server/.env` (образец — `apps/server/.env.example`, файл `.env` в git не попадает). Если `.env` нет, сервер при первом старте сгенерирует пароль и напечатает его: `docker compose logs server`.
- Демо-аккаунты: `coordinator` (Специалист), `admin` (Администратор), `viewer` (Просмотр); для кабинета бригады — `foreman1`, `foreman2`, `worker1`…`worker4`.
- Открыть с другого компьютера в сети: добавьте его адрес в `ALLOWED_HOSTS` в `apps/server/.env`.

Для разработки (Node.js 24):

```bash
npm --prefix apps/web install
npm --prefix apps/web run dev
```

Откройте http://localhost:5173. Данные — из **тестового источника в браузере**: он эмулирует сервер `/api/v1` по контракту. Демо-роли переключаются в «⚙ Режим проверки»: Специалист, Администратор, Просмотр, а для дополнительного модуля работ — Бригадир и Работник.

С настоящим сервером: запустите его (ниже) и откройте http://localhost:5173/?source=api. Vite проксирует `/api` на `http://127.0.0.1:3100` (переопределяется `VITE_API_PROXY`).

```bash
npm --prefix apps/server install
cp apps/server/.env.example apps/server/.env
npm --prefix apps/server run seed:tz
npm --prefix apps/server run dev
```

## Сервер и режим api

**Маршруты ТЗ на сервере** (`apps/server/src/tz/routes.ts`) отвечают в том же формате, что тестовый источник: `POST /zones`, `POST /zones/:id/analysis`, `POST /zones/:id/variants`, `GET /zones/:id/context`, `GET /problems`, `POST /priorities` (с дорожной картой), `GET` и `PATCH /rates` (правит администратор, источник обязателен, история — `GET /rates/history`), `GET /layers/soils`, `GET /layers/greenery`, `GET /species`, `GET /dashboard/metrics`, `POST /assistant`, `GET /assistant/history`, `POST /imports/preview`. Расчёты сервер не копирует: он загружает те же модули `apps/web/src/shared/analytics` через tsx, поэтому цифры в mock и api совпадают (это проверяет тест). Результат `analyzeZone` кэшируется по ключу «зона и её версия, параметры, версия расценок».

**Слой соответствий — одно место:** `apps/web/src/shared/api/v2compat.ts`, подключается только в режиме `?source=api`. Он сводит имена контракта экранов и контракта V2 сервера: brigades ↔ crews, projects ↔ designs (designVersion ↔ revision, returned ↔ changes_requested), species ↔ plant-catalog (id вида = id позиции каталога), assigneeId и crewIds ↔ assignedWorkerIds, minCrew ↔ minWorkers, `checks.state` ↔ `checks.status`, а также коды ошибок V2 (`VERSION_CONFLICT` → `version_conflict`). Сервер не переименовывает поля V2, потому что на них работает кабинет бригады. Расчётам ТЗ сервер передаёт участок через ту же функцию `siteFromV2`. CSRF-токен и разворачивание `{user, csrfToken}` в `Me` — в `transport.ts`.

**Ассистент на модели (ТЗ 3.10).** Сервер подключает любую модель с OpenAI-совместимым API: Gemini, Groq, DeepSeek, Grok или локальную Ollama. Готовые блоки для `apps/server/.env` — в [`apps/server/env-templates/`](apps/server/env-templates/README.md): Groq + Gemini (бесплатно, рекомендуется: ответ ≈1,5 с), вариант с локальной Ollama для работы без интернета, DeepSeek, Grok. Адреса, модели и хосты в них заполнены — вставьте только ключи в `LLM_API_KEY` (основная) и `LLM2_API_KEY` (резерв). Проверка до запуска: `npm --prefix apps/server run llm:check` — покажет, принят ли ключ, есть ли модель у провайдера, вызывает ли она функции и за сколько секунд отвечает. Затем перезапустите сервер. В журнале появятся строки `Assistant model: …` и `Assistant reserve 1: …`. Если основная упёрлась в лимит (ответ 429), упала или не успела, отвечает резервная; после 429 основная пропускается до конца Retry-After или на минуту. Модель сама ничего не считает: она вызывает функции сервера (`analyze_zone`, `compare_variants`, `top_priorities`, `budget_roadmap`, `find_problems`, `search_zones`, `search_knowledge`), а цифры в ответе берутся из их результатов. Под каждым ответом видно метод, вызванные расчёты и источники. Если ни одна модель не настроена, не ответила за `LLM_TIMEOUT_MS` или назвала цифры без расчёта, отвечают правила, и это помечено. В модель уходят вопрос, данные зон и результаты расчётов; имена пользователей — нет. Код — `apps/server/src/tz/llm.ts`.

**Роли — одно правило для сервера и тестового источника:**

| Роль | Может | Не может |
|---|---|---|
| Специалист (`coordinator`) | анализ зон и варианты, рисование зоны, отметки проверок, проекты (создать, править, отправить, отозвать), задания и их назначение, проверка отчётов | согласовать свой проект, менять справочники |
| Администратор (`admin`) | справочники (расценки, каталог), пользователи и бригады, согласование проектов, отметки проверок участков; читает всё | задания, назначение бригад, проверку отчётов, проекты и зоны — это работа специалиста (разделение «готовит — согласует») |
| Просмотр (`viewer`) | читать всё по ТЗ и запускать расчёты без сохранения (анализ, варианты, приоритеты, ассистент) | любые изменения |

Сервер проверяет права сам, интерфейс их только отражает. Изменяющие запросы требуют сессию, `X-CSRF-Token` и `Idempotency-Key`; правки — `expectedVersion`.

## Данные, допущения и ограничения

- **Проверенные данные о Павлодаре** — [`fixtures/pavlodar`](fixtures/pavlodar/README.md): 34 открытых источника и 33 факта (климат 1991–2020, нормы отступов СП РК, правила озеленения области, воздух, зелёный фонд, цены госзакупок). Видны в «Справочниках», на них ссылается ассистент, отступ от здания в проверке посадок — по СП РК. Население и границы микрорайонов, цены на саженцы и акты приживаемости в открытых источниках не найдены.
- **Зоны** — 114 газонов и пустырей из OpenStreetMap (ODbL), снимок 27.10.2026. Это кандидаты, а не подтверждённо свободная земля.
- **Почвы** — *синтетический* слой (ячейки 400 м) до получения карты почв организатора. Помечен на карте и в расчётах.
- **Насаждения** — OSM (парки, скверы, деревья); деревья в OSM нанесены неполно.
- **Растения** — 50 видов; польза и устойчивость — обобщение команды (оценка). «Сажают в Павлодаре» — со ссылкой на источник.
- **Приживаемость** — логистическая регрессия на синтетических данных из экспертных правил; метрики измерены на синтетической проверке, модель *не калибрована* на реальных посадках Павлодара. Правила доступны отдельно для сравнения; подробности и границы диапазона — [docs/survival-model.md](docs/survival-model.md).
- **Смета** — демо-расценки команды; администратор заменяет их в «Справочниках».
- **Экоэффект** — коэффициенты с источниками (CO₂ ≈25 кг/год на взрослое дерево, задержание дождя ≈2228 л/год, охлаждение 0,8–1 °C). Для пыли и населения данных нет — показываем «нет данных».
- **Ассистент** — сейчас разбор запросов по правилам поверх модулей; LLM + RAG подключается на сервере адаптером (`TzOptions.assistant`), ключ — только в `apps/server/.env`, хост модели — в `LLM_ALLOWED_HOSTS`.
- Персональные данные граждан не обрабатываются.

Все результаты оценочные и носят рекомендательный характер; решение принимает специалист акимата.

## Краткая инструкция (1 страница)

1. **Карта** → включите слои справа → нажмите на зону.
2. В карточке зоны: **Растения** (закрепите или исключите виды) → **Смета** (выберите вариант) → **Приживаемость** (примените меры) → **Уход** → **Эффект**.
3. **⤓ Отчёт по зоне** → «Печать / PDF» или «Excel».
4. **Приоритеты** → задайте веса и бюджет → получите очерёдность.
5. **Проблемные зоны** → фильтр по типу и остроте → переход к зоне на карте.
6. **✦ Ассистент** → спросите своими словами, например: «что можно озеленить на 50 млн».


## Проверки качества и покрытие

[Quality](.github/workflows/quality.yml) запускается на pull request в `codex/coordinator`
и push в эту ветку. Три независимых задания используют Node 24: веб (типы, сборка,

`npm run test:coverage` использует [встроенное покрытие Node](https://nodejs.org/docs/latest-v24.x/api/test.html#collecting-code-coverage),
без дополнительной библиотеки и без порога. Esbuild создаёт общие ESM-фрагменты и
связанные source maps с исходным текстом; сторонние пакеты остаются внешними.
Тот же набор тестов измеряется последовательно в одном процессе: это устраняет
повторные копии модулей и зависимость счётчиков source maps от порядка объединения
процессов. Обычный `npm test` сохраняет изоляцию файлов тестов отдельными процессами.

Измерено **30.10.2026**, Windows, Node **v24.17.0**, чистый коммит
`f82f4015b2cf819ae8ddc5a78fa16e7e11c6e5bb`: **169 тестов**, отчёт по **52 исходным TS/TSX-файлам**.
Повторные измерения совпали по каждому файлу.

| Метрика | Покрыто / учтено | Процент |
|---|---:|---:|
| Строки | 2999 / 5650 | 53,08% |
| Ветви | 1641 / 1903 | 86,23% |
| Функции | 579 / 763 | 75,88% |

Это покрытие исходников, достигнутых данным набором Node-тестов и сопоставленных
встроенным экспериментальным механизмом Node, **не всего приложения**. В знаменатель
не входят незагруженные файлы, тесты, `node_modules`, fixtures, JSON-данные и диапазоны,
которые Node не смог сопоставить с исходниками. Показатель не измеряет браузерные
сценарии, сервер или визуальное качество. Не следует складывать его с результатами E2E.

После запуска доступны `apps/web/dist-tests/coverage/lcov.info` и `summary.json`.
JSON содержит дату, Node, SHA, признак незакоммиченных изменений, список файлов,
исключения и числители/знаменатели. CI сохраняет эти два отчёта как артефакт на семь
дней. Старые отчёты удаляются перед измерением; пустой отчёт, дубли путей или строки
из bundle вместо `src` считаются ошибкой, а не успешным измерением.

Прямые тесты `v2compat` проверяют соответствия сайтов, проверок, задач, бригад,
проектов/согласованных ревизий, отчётов и ошибок; отдельно — версии, ключи повторов,
пагинацию и передачу ошибок API. Сами преобразования этим изменением не переписываются.

Playwright остаётся отдельной приёмкой в `tools/e2e`. Дополнительное задание E2E в CI
пока не включено: расширенный набор #16 нужно проверить вместе с исправлением #20
на интегрированной версии. При создании ветки `main` для жюри капитан должен добавить
её в фильтры workflow; текущие фильтры относятся только к `codex/coordinator`.
