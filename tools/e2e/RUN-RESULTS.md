## Ограничения и следующий шаг

Docker **не проверен**: повторная проверка 30.10 подтверждает, что docker version не может открыть `//./pipe/dockerDesktopLinuxEngine`; apps/server/.env отсутствует. Не проверены сборка/запуск Compose и mock/API через :8080. После всех согласованных вливаний сначала согласовать с пользователем конкретную сборку: исходный SHA, происхождение образов и image IDs/digests, адрес и изолированный seed. Затем на настроенном стенде: из чистого checkout этого SHA `docker compose up --build`; в tools/e2e `$env:E2E_BASE_URL='http://localhost:8080'`, затем `npm.cmd run e2e` и `npm.cmd run e2e:api`, короткий сценарий из матрицы. Пароль берётся из окружения или локального .env без печати. Открытый #22 подготовки deployment сам по себе не доказывает доступность или проверку сборки.

ZIP/XML не заменяет визуальное открытие в настольном Word. Лингвистическую точность видов проверяет Бекзат. В тестах используются локальные копии тех же Manrope/Oswald с OFL-лицензиями и SHA-256; доступность Google Fonts в сети не проверяется. Фотографии и подложка по-прежнему используют сеть; карта может показывать штатную схему. Презентация на конкретном проекторе и видео — отдельная работа команды.

Устаревший PR #3 закрыт без вливания. PR #16 остаётся открытым → codex/coordinator. После исправления E2E-06 — merge, повтор матрицы и полного mock/API, обновление PR. После подтверждения merge #16 новые outcomes-проверки вести в `codex/outcomes-e2e`. Финальная приёмка свежей coordinator — после всех согласованных вливаний, на одном зафиксированном SHA; текущие результаты её не заменяют.

К защите подтверждены прежние сценарии специалиста RU/KK, Word структурно, карта/приоритеты/ассистент и мобильный кабинет.
