# Инструменты перед демонстрацией

Все команды выполняются из `tools/e2e`. В Windows PowerShell при запрете запуска npm.ps1 используйте `npm.cmd` и `npx.cmd`.

| Команда | Для чего | Результат |
|---|---|---|
| `npm run e2e:doctor` | Проверить Node, закреплённый Playwright, запуск Chromium, WebGL и зависимости веба | Диагностика без изменения приложения, `playwright-report/doctor/results.json` |
| `npm run e2e:doctor -- --api --docker` | Проверить наличие пароля, health API/SQLite, Docker Engine и `.env` | Значения паролей и содержимое `.env` не выводятся; контейнеры не запускаются |
| `npm run e2e:smoke` | Быстро проверить 13 страниц и четыре ключевых сценария на desktop | 17 проверок; отдельные `test-results/smoke` и `playwright-report/smoke` |
| `npm run e2e:smoke -- --project mobile` | Те же проверки на телефоне | 375×812; результаты полного mock не перезаписываются |
| `npm run e2e:screens` | Переснять только материалы для слайдов | 30 PNG, оба размера, режим презентации; отдельный отчёт `screens` |
| `npm run e2e:summary` | Собрать доступные результаты в общий отчёт | `playwright-report/summary/index.html`, `results.json` и `DAMIR.md` |
| `npm run e2e:pack` | Передать команде пакет для просмотра без сервера | `playwright-report/summary/green-pavlodar-demo.zip`: отчёт, сводка, JSON и только свежие PNG; полный набор — 30 |
| `npm run e2e:gate` | Строго проверить полноту mock + API | Exit 0 только для полных успешных прогонов на текущем чистом коммите; иначе exit 1 |
| `npm run check:tools` | Проверить сами инструменты | Проверки классификации результатов, секретов, свежести и безопасного HTML |
| `npm run check:report` | После `e2e:pack` проверить отчёт в браузере | Поиск, фильтры, галерея, клавиатура, ширина desktop/mobile и точный состав ZIP |

Отчёт содержит поиск по сценариям, фильтры статуса/прогона, галерею desktop/mobile, просмотр изображения полностью и печать в PDF. После любого обычного тестового запуска сводка обновляется автоматически. Для просмотра распакуйте весь ZIP и откройте `index.html`; интернет не нужен. API-трассы, журналы, локальные базы и `.env` в ZIP не включаются.

Режимы `mock`, `api`, `smoke`, `screens`, `bugs` сохраняют результаты отдельно. В `playwright-report/runs/` записываются время, ревизия, наличие локальных изменений, адрес без параметров и код завершения. Пароли, произвольные аргументы и переменные окружения туда не записываются. Результат без метки запуска показывается как прежний отчёт без подтверждения свежести.

`fixme` остаётся нерешённым дефектом, `skip` — невыполненной проверкой, `flaky` — нестабильным результатом. Gate допускает только два заранее известных пропуска мобильных сценариев в desktop-проекте. Отсутствие пароля API, выборочный запуск, другой коммит, локальные изменения, повреждённый отчёт или свежий неудачный запуск поверх старого отчёта не дают успешную приёмку. Docker и ручной показ жюри проверяются отдельно.

Перед показом: `npm run e2e:doctor` → `npm run e2e:smoke`. Для материалов: `npm run e2e:screens` → просмотр и подтверждение текущего runId → `npm run e2e:pack`. Для полной приёмки: чистый коммит → полный mock → изолированный API → просмотр и утверждение снимков → summary → check:report → pack → check:report → gate. Исторический контроль 932574e: полный mock 283/1/2, API 74/0. После #35 на 84d009e прошли E2E-11 (8 mock + 4 API) и навигация (8 mock + 16 API). Это точечные наборы; полного прогона новой версии нет. PR #43 остаётся Draft до согласованной итоговой приёмки. Контрольный ZIP с 30 кадрами относится только к 932574e и помечен diagnostic-not-accepted. Публичный API проверен только без авторизации; итоговый прогон ожидает финальный SHA, доступ и окно публикации. Точные версии и ограничения — в [RUN-RESULTS.md](RUN-RESULTS.md).

При падении функционального mock-прогона все его результаты сохраняются; отдельный успешный `e2e:screens` позволяет обновить 30 PNG и пакет демонстрации после просмотра, но не меняет статус полной приёмки. Включённые проверки #14 — в [PR14-CHECKLIST.md](PR14-CHECKLIST.md). Безопасные воспроизведения — в [BUGS.md](BUGS.md) и `evidence/`. Автоматические API-снимки, trace и error-context не сохраняются. Отдельные Docker-кадры допускаются только из согласованной синтетической QA-среды, без секретов и после визуальной проверки.

У API проверяется реальный `/api/v1/auth/me` через выбранный стенд (ожидается JSON 401 без сессии). `/health` с проверкой SQLite доступен непосредственно на сервере: адрес берётся из `VITE_API_PROXY` или локального :3100 без `E2E_BASE_URL`. Для Docker через один только веб-адрес отсутствие прямого `/health` отмечается как непроверенная база, а HTML веб-приложения не считается здоровым API.

Для просмотра до замены материалов: в PowerShell задайте `$env:E2E_SCREEN_REVIEW='1'` и запустите `npm.cmd run e2e:screens`. Кандидаты попадут в `test-results/screen-review/`. Возьмите runId из `playwright-report/runs/screens.json`, выполните `node scripts/review-screens.mjs --run-id UUID --list`, просмотрите все 30 PNG и только затем выполните ту же команду с `--approve`. Подтверждение связано с точными SHA/runId/хэшами; вручную переносить PNG не нужно. Обычные команды без этой переменной сохраняют снимки в `screens/`. Действующий лимит снимков — 90 с, включая готовность шрифтов и видимых фотографий; его не увеличивали для этой приёмки.

Шрифты Manrope/Oswald в mock/API воспроизводятся из `fixtures/fonts/` без изменения байтов; OFL-лицензии и SHA-256 сохранены. Это устраняет зависание тестов на Google Fonts. Запросы приложения, API, фотографии и карта этой fixture не подменяются; доступность самого font-CDN проверяется отдельно.
