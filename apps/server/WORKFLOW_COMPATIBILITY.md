# Совместимость workflow — PROPOSED, 27 октября 2026

Официальное задание и общий контракт ещё не получены. Ни один новый статус
не объявляется окончательным. Оба варианта реально работают локально.

| Смысл | Существующий API | Изолированный эксперимент |
|---|---|---|
| Создать без исполнителя | Не поддерживается | `draft` |
| Назначить исполнителя | `pending` уже содержит `assignedToId` | `draft → assigned` |
| Начать работу | `pending → in_progress` | `assigned → in_progress` |
| Отправить отчёт | `in_progress → completed` | `in_progress → submitted` |
| Проверить координатором | Не предусмотрено | `submitted → verified` |
| Вернуть с комментарием | Не предусмотрено | `submitted → assigned`, комментарий обязателен |
| Отменить | `pending/in_progress → cancelled` | BLOCKED: правило отмены не согласовано |

`pending` приблизительно соответствует `assigned`, потому что существующий POST
сразу требует исполнителя. `completed` означает только отправленный работником
отчёт: его нельзя автоматически считать `verified`. Даже преобразование в
`submitted` требует согласования судьбы старых отчётов, фотографий и истории.
Автоматического переноса между моделями нет.

## Изоляция

`src/experimental-workflow.ts` и маршруты `/experimental/...` работают с таблицами
`experimental_tasks`, `experimental_reports`, `experimental_task_history`,
`experimental_photos`. Справочники растений, участков и DEMO-пользователей общие.
Обычные `/tasks` и `/reports`, их статусы и данные сохранены. Миграция v1 → v2
добавляет таблицы, не переписывая существующие записи.

## Фактические правила эксперимента

- Координатор создаёт draft с ровно одной целью: растение или участок.
- Координатор назначает существующего worker; повторное назначение разрешено
  только в `assigned`. Пустое/то же назначение не создаёт фиктивной истории.
- Только текущий назначенный worker начинает работу и отправляет отчёт.
- Отправка создаёт новую ревизию Report и переводит Task в `submitted`.
- Фото добавляет только автор, который остаётся назначенным работником,
  пока эта ревизия `submitted`. Фото увеличивает версию Task и записывает историю.
- Координатор подтверждает или возвращает последний submitted-отчёт.
  `return` без непустого комментария отвергается. Предыдущая ревизия сохраняется
  со статусом `returned`; после повторного начала работы создаётся следующая.
- Verified-отчёт и его фотографии через эти API больше не изменяются.
- Каждая запись требует актуальную `version` и `Idempotency-Key`. Переход,
  изменение отчёта, история и ключ повтора фиксируются одной транзакцией.
- Отчёты/историю читает координатор либо текущий исполнитель задания.
  Чужой Task/Report/Photo ID возвращает 404. После переназначения прежний
  исполнитель теряет доступ; новый видит предыдущие ревизии своего задания.
