## 1. Готовая основа

Изолированный локальный прототип: Node.js 24, TypeScript, Express 5, SQLite через
встроенный `node:sqlite`. Публичных операций с GitHub, деплоя и подключений к общим
БД нет. Изменений в исходном репозитории нет. Коммитов автоматически не создавалось.

Готовы строгие DTO, девять черновых сущностей, параметризованные SQL-запросы,
FK/CHECK-ограничения, WAL, транзакции, начальная версия схемы `user_version=1`,
`/health`, восемь прикладных маршрутов, локальная симуляция ролей, история,
оптимистическая версия задания, идемпотентность всех POST/PATCH, лимит JSON 32 KiB,
безопасные сообщения ошибок и проверяемые примеры PowerShell.

Seed создаёт 30 растений, 6 участков, 3 работников, 1 координатора, 15 заданий,
30 синтетических ссылок-источников и 15 начальных записей истории.
Названия помечены `DEMO`; координаты вымышленные и не подтверждают наличие объектов.
Повторный seed не обновляет/не удаляет существующие записи: только
`INSERT ... ON CONFLICT(id) DO NOTHING`. История добавляется только при вставке
нового seed-задания. Ошибки других ограничений не скрываются, seed откатывается целиком.

## 3. Команды и API

Из корня проекта: `npm ci` при чистой установке; `npm run seed`; `npm run dev`.
Для сборки: `npm run typecheck`, `npm run build`, `npm test`, `npm run smoke`, `npm start`.
Существующий `.env` не перезаписывать. Без `.env` действуют безопасные значения по умолчанию.

Маршруты: `GET /health`, `GET /plants`, `GET /plants/:id`,
`GET /candidate-sites`, `GET /workers`, `GET /tasks`, `POST /tasks`,
`PATCH /tasks/:id`, `POST /reports`. Дополнительных продуктовых endpoints нет.

## 4. Предварительные решения

Все имена полей, URL, статусы, правила доступа, схемы ответов и ошибок — черновые.
Работник видит/изменяет только свои задания, координатор видит все.
Только координатор создаёт и назначает задания; работник начинает задание
и завершает его отчётом. Чужое задание возвращает 404 без раскрытия записи.
Назначение возможно только на существующего работника.

Каждое задание относится к одному Plant либо одному CandidateSite.
Статусы: `pending`, `in_progress`, `completed`, `cancelled`.
Один итоговый Report на Task; ревью координатором, повторное открытие и черновики
отчётов пока не реализованы. `version` — целое число в теле, не HTTP ETag.

Поля `Observation`, `Photo`, `EvidenceRef` пока только в DDL; источники синтетические,
внешние URI не запрашиваются. Observation/Photo без записи/чтения через HTTP.
TaskHistory сохраняет снимок после каждой версии; автор и время берутся на сервере.
Автоматические удаления и очистка идемпотентности отсутствуют.

## 5. Надёжность и границы безопасности

- SQLite-файл сохраняется после перезапуска. WAL и `BEGIN IMMEDIATE` защищают
  атомарность записи; отдельные обновления дополнительно проверяют текущую версию.
- Схема создаётся один раз в транзакции; неизвестная версия вызывает ошибку,
  база не сбрасывается. Миграции v2+ ещё не согласованы.
- POST/PATCH атомарно сохраняют бизнес-результат и ключ повтора с хешем DTO.
  Ключ ограничен пользователем, HTTP-методом и путём. Порядок полей JSON не важен.
  Успешные ответы кэшируются; неуспешные можно повторить после устранения причины.
- `X-Demo-User` — исключительно тестовая идентичность. Это не пароль и не токен;
  локальный клиент может выбрать другого DEMO-пользователя.
  Loopback, запрет `production`, Origin и чужих Host ограничивают прототип локальной работой.
- Настоящая аутентификация, CORS для UI, управление пользователями, rate limiting,
  аудит входов, бэкапы и восстановление пока не внедрены.
- Загрузки фотографий отключены. Multipart не принимается, файловый сервер отсутствует.
  DDL ограничивает размер/тип/имя/хеш только зарезервированных метаданных.
  До открытия upload нужно согласовать декодирование и повторное кодирование изображений,
  проверку сигнатуры, случайные имена, хранение вне web-root, удаление EXIF,
  лимиты, права доступа, правила хранения и очистку.
- Синхронный SQLite достаточен для подготовки и коротких локальных транзакций;
  производительность под реальной нагрузкой не измерена.
- `.env`, SQLite, `node_modules`, `dist` исключены из Git. `.env.example` без секретов.
  Публичные зависимости скачаны из npm; секреты во внешние сервисы не передавались.
- Не удалять рабочую SQLite-базу для обновления схемы. Перед переносом остановить
  сервер, закрыть соединения и сделать отдельную локальную копию базы.
