5. КОНТРАКТ
Маршруты /api/v1 и их типы — в apps/web/src/shared/api/types.ts и api.ts, хранитель — участник 2. Типы результатов расчётов — в shared/analytics, хранитель — участник 3. Тестовый источник и настоящий сервер отдают одинаковые ответы в обёртке {data, meta} или {error}. Перед изменением контракта — сообщение в чат команды, потом PR с ревью затронутого участника.

Новые точки контракта на эти дни:
- POST /api/v1/zones с телом {name?, geometry: GeoJSON Polygon} возвращает CandidateSite с id вида site-user-N: площадь, центр, окружение, почва. Нужна для нарисованной зоны. Делает участник 2 (сначала в mock, потом на сервере), использует участник 1.
- POST /api/v1/assistant: AssistantReply получает поля method ('model' или 'rules'), sources ([{id, label, url?}]) и toolCalls ([{name, args}]). Логика — участник 3, маршрут на сервере — участник 2, показ — участник 1.
- GET /api/v1/assistant/history — хранит участник 2, показывает участник 1.
- POST /api/v1/zones/:id/care-schedule с телом {months, crewVisitsPerMonth?, budgetKzt?} возвращает {tasks: черновики заданий, warnings, method}. Логика — участник 3, маршрут и сохранение заданий — участник 2, кнопка в карточке зоны — участник 1, задания в кабинете бригады — участник 4.

6. ПРАВИЛА ДЛЯ КОДА И ДАННЫХ
- Интерфейс на русском, все строки — в shared/i18n/ru.ts. ID — строки. Даты — ISO 8601 в UTC, на экране UTC+5. В GeoJSON порядок координат строго [lng, lat].
- Неизвестное значение — null и запись в missingData, а не 0. Ничего не выдумывать: нет данных — так и пишем «нет данных» (п. 5.5 ТЗ).
- Все результаты помечены как оценка (п. 5.2). У каждого коэффициента есть источник (п. 5.3). Синтетические данные помечены как синтетика.
- Ключи и пароли — только в .env на сервере. Никогда в браузерном коде и никогда в git.
- Режим mock должен работать всегда: это запасной вариант на защите. Не ломай его.
- Никакого force push в общие ветки. Не перезаписывай чужие незакоммиченные изменения. Не копируй папки из одной ветки в другую — только git merge.
