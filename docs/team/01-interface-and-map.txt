ЗАДАЧИ

MAP-01 — Рисование зоны, P0.
Кнопка «Нарисовать зону» на карте. Клик ставит вершину, двойной клик или «Готово» завершает, Esc отменяет. Во время рисования видна площадь в м². Проверяй самопересечение и минимальную площадь 50 м², ошибку показывай понятным текстом. По «Готово» вызывай api.createZone({name, geometry}), это POST /api/v1/zones. Если участник 2 ещё не добавил её в тестовый источник, договорись с ним, добавь заглушку сам и отметь это в PR. Затем открой карточку новой зоны со всеми вкладками. Работает в 2D и 3D. Своя реализация через GeoJSON-источник MapLibre надёжнее стороннего плагина рисования.

MAP-02 — Поиск по адресу, P0.
Поле поиска над картой. Сначала ищем по локальным данным: названия зон и улицы из окружения в fixtures/osm. Если есть интернет — дополнительно Nominatim (OpenStreetMap) в границах Павлодара, с задержкой ввода 500 мс и не чаще одного запроса в секунду. Выбор результата приближает карту: если точка внутри зоны — выбирает её, если нет — предлагает нарисовать зону. Без интернета поиск по локальным данным работает.

MAP-03 — Карточка зоны и сравнение вариантов, P0.
Пройди руками: Растения (закрепить, исключить, заменить) → Смета (эконом, оптимальный, максимальный) → Приживаемость (применить меры) → Уход → Эффект. Любое изменение пересчитывает все вкладки. Сделай наглядное сравнение вариантов (3.4.3): таблица на три колонки — стоимость, число растений, приживаемость через 3 года, CO₂ за 20 лет, ₸ за тонну CO₂; лучшее значение в строке выделено. Из списка подобранных растений открывается карточка вида (SpeciesCardFull): фото, требования, цена и почему вид подходит именно этой зоне. Везде значок «оценка», а вместо нулей — «нет данных».

MAP-04 — Ассистент в боковой панели, P1.
AssistantPanel: история запросов (api.assistantHistory уже есть в api.ts, но на экране не используется), значок метода «модель» или «правила», список источников, ссылки на зоны. Ответ «данных нет» выглядит как предупреждение, а не как ошибка. Быстрые кнопки с четырьмя примерами запросов из ТЗ 3.10.1. Новые поля AssistantReply (method, sources, toolCalls) добавляет участник 3.

MAP-05 — Кнопка «Предложить график ухода», P1.
Во вкладке «Уход» кнопка вызывает POST /zones/:id/care-schedule и показывает предложенные задания по месяцам и предупреждения. Кнопка «Создать задания» сохраняет их через api, сохранение — на стороне участника 2. Для роли «Просмотр» кнопки скрыты.

MAP-06 — Точки и фильтры, P1.
На карте точками: существующие растения, планируемые посадки, задания бригад с цветом по статусу (draft, assigned, in_progress, submitted, verified), подсказка по клику. К фильтрам в filters.ts добавь тип проблемы, остроту, диапазон приоритета, назначение зоны и счётчик «показано N из M». Состояние фильтров храни в параметрах адреса, чтобы ссылку можно было переслать.

MAP-07 — Скорость и состояния, P1.

5. КОНТРАКТ
Маршруты /api/v1 и их типы — в apps/web/src/shared/api/types.ts и api.ts, хранитель — участник 2. Типы результатов расчётов — в shared/analytics, хранитель — участник 3. Тестовый источник и настоящий сервер отдают одинаковые ответы в обёртке {data, meta} или {error}. Перед изменением контракта — сообщение в чат команды, потом PR с ревью затронутого участника.

Новые точки контракта на эти дни:
- POST /api/v1/zones с телом {name?, geometry: GeoJSON Polygon} возвращает CandidateSite с id вида site-user-N: площадь, центр, окружение, почва. Нужна для нарисованной зоны. Делает участник 2 (сначала в mock, потом на сервере), использует участник 1.
- POST /api/v1/assistant: AssistantReply получает поля method ('model' или 'rules'), sources ([{id, label, url?}]) и toolCalls ([{name, args}]). Логика — участник 3, маршрут на сервере — участник 2, показ — участник 1.
- GET /api/v1/assistant/history — хранит участник 2, показывает участник 1.
- POST /api/v1/zones/:id/care-schedule с телом {months, crewVisitsPerMonth?, budgetKzt?} возвращает {tasks: черновики заданий, warnings, method}. Логика — участник 3, маршрут и сохранение заданий — участник 2, кнопка в карточке зоны — участник 1, задания в кабинете бригады — участник 4.

6. ПРАВИЛА ДЛЯ КОДА И ДАННЫХ
- Интерфейс на русском, все строки — в shared/i18n/ru.ts. ID — строки. Даты — ISO 8601 в UTC, на экране UTC+5. В GeoJSON порядок координат строго [lng, lat].
- Неизвестное значение — null и запись в missingData, а не 0. Ничего не выдумывать: нет данных — так и пишем «нет данных» (п. 5.5 ТЗ).
- Все результаты помечены как оценка (п. 5.2). У каждого коэффициента есть источник (п. 5.3). Синтетические данные помечены как синтетика.
- Ключи и пароли — только в .env на сервере. Никогда в браузерном коде и никогда в git.
- Режим mock должен работать всегда: это запасной вариант на защите. Не ломай его.
- Никакого force push в общие ветки. Не перезаписывай чужие незакоммиченные изменения. Не копируй папки из одной ветки в другую — только git merge.
