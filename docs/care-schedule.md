# Черновики ухода, контракт 29.10

`POST /api/v1/zones/:id/care-schedule`: `{ months: 1..12, crewVisitsPerMonth?: 0..31, budgetKzt?: number >= 0 }`. Все числа конечные; months и crewVisitsPerMonth целые. Ответ: `{ data: { tasks: CareDraft[], warnings: string[], method: "rules" } }`. Это расчёт без записи: coordinator/admin/viewer могут просматривать, создавать задания может только coordinator. Реальный POST требует сессию и CSRF, ключ идемпотентности для расчёта не нужен.

Сервер загружает `shared/analytics/careSchedule.ts` через существующий tsx-мост. Mock использует ту же функцию. Календарь берётся из `careCalendar`; в строках добавлены необязательные структурированные action и объём на визит. Для цветников добавлена отдельная июньская прополка как экспертный ориентир. Нет второй таблицы месяцев ухода.

Горизонт — следующие **полные** календарные месяцы по UTC+5. Для каждого визита вычисляется отдельный ориентировочный срок, равномерно внутри месяца в 12:00 местного времени. Настройки предложения посадки во вкладке не меняют этот график: он строится для фактически зарегистрированных растений с базовым регулярным уходом. Это явно указано в интерфейсе.

Принадлежность — координата зарегистрированного растения внутри Polygon, с исключением внутренних колец. Соседство и позиции непринятого проекта не создают растения. У V2 нет поля siteId в Plant; при перекрывающихся контурах специалист должен исключить дубли между зонами. Вид сопоставляется по speciesId или единственному точному латинскому названию; неизвестный вид → только осмотры. Без растений → ежемесячные осмотры участка и предупреждение. Точечная зона не задаёт контур; для неё растения не подбираются.

`water` и `weed` направляются только на `plant`. Неподдерживаемые действия календаря (обрезка, побелка, удобрение и т.д.) становятся **осмотрами необходимости работ**, а не заданиями выполнить эти работы. Посадка через этот маршрут не назначается. Без центра зоны почва остаётся неизвестной, мелиорация не добавляется. Для цветника без площади и влагозарядкового полива без нормы вода `null`; при отсутствии нормы дерева/куста также `null`.

Черновик содержит поля NewTask и `id`, `objectName`, `estimatedCostKzt: null`, `dataClass: "estimate"`. Длительность — явно подписанное допущение команды: 15 минут осмотра, 20 минут полива/прополки. Это ориентир, не норматив. Расценок на отдельные операции нет, поэтому budgetKzt вызывает предупреждение о невозможности проверить бюджет, а не выдуманную смету. crewVisitsPerMonth сравнивается с количеством различных предложенных дат за месяц; превышение предупреждает, но не удаляет необходимый уход. Маршрутизация и вместимость бригады ещё не рассчитаны.

Кнопка «Создать» передаёт только поля NewTask через существующий `api.createTask`. Результат каждой строки виден отдельно. При сетевом сбое повторяется тот же ключ и тело запроса; повторное формирование в открытой панели сохраняет статусы. Перезагрузка страницы или другой пользователь не имеют общего реестра выпущенных графиков: перед повторным выпуском нужно проверить список заданий. Назначение бригады и приёмка остаются в существующем процессе.

Проверки: `npm --prefix apps/web run check:care` (mock, повтор, права, неизвестное, границы/внутренние кольца, календарный год); серверный `tz.test.ts` проверяет одинаковый результат общей функции, сохранение plant-water и site-inspect, валидацию, права, идемпотентность и запрет полива участка.

## Демо полива в mock

В зоне **«Газон, проспект Нурсултана Назарбаева»** (`site-osm-1490224716`) добавлены три зарегистрированных демо-растения: вяз, сосна и карагана. ID: `plant-care-demo-1`…`plant-care-demo-3`; у всех `isDemo: true`, название с пометкой «демо» и источник `ev-demo-scenario`. Координаты и дата высадки синтетические, не городской реестр. Для показа полива в октябре выберите горизонт **12 месяцев**, чтобы захватить май–октябрь следующего года; зимой календарь не назначает обычный полив.

Существующее хранилище mock обновляется добавлением недостающих примеров с маркером `careDemoVersion=1`: задания, проекты, пользовательские растения и отредактированные примеры сохраняются. Сброс mock не нужен. В серверный реестр V2 эти примеры не импортируются. `check:care` проверяет их положение в зоне, демо-пометки, полив растений и повторяемость миграции.
