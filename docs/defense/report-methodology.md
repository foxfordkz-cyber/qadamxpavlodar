# Источники и проверка демонстрационного отчёта

## Воспроизведение данных

Пакет использует настоящий расчёт `analyzeZone`, `priorities`, `roadmap`, `detectProblems` из текущего исходного кода на fixtures. Существующий `docs/example-report.md` не изменён. Контрольные числа совпали с этим сохранённым примером от 28.10.2026.

- База: `18c254109478e336beab220f5e492701b29c2897`.
- Зона: `site-osm-1569993037`, «Газон, улица Толстого», 3 782 м².
- Параметры: `variant=optimal`, `careYears=3`, полив regular, без улучшения почвы, лимит доли вида 0,3.
- Источники: `fixtures/osm/sites.json`; `apps/web/src/shared/api/mock/species.ts`; `apps/web/src/shared/analytics/{zone,rates,plan,city}.ts`.
- Пересчёт: 29.10.2026, Node v24.19.0. Промежуточный набор и SHA-256 источников: `qadam-defense/work/demo-data.json`; воспроизведение: `qadam-defense/work/generate-demo-data.mjs`.

Контрольные результаты: смета **10 839 718 ₸**; **54 дерева, 270 кустарников, 1 021 цветок**; средняя приживаемость **83 / 81 / 79%**. Дорожная карта на 50 млн ₸: 29 зон, 49 779 198 ₸, остаток 220 802 ₸.

**Отличие от живого mock:** генератор использует исходный OSM fixture, где доступ к воде неизвестен. UI mock seed дополнительно задаёт этой зоне `waterAvailability=70` и проверки участка. При тех же optimal/3 года живой mock показывает **10 831 618 ₸**, то есть резерв ниже на **8 100 ₸**. Это разные входные состояния, а не ошибка переноса сумм. Не обещать совпадение отчёта с UI, пока не согласованы и эти факторы. В записи mock сохраняется фактическая цифра интерфейса.

## Как трактовать показатели

- Почвы синтетические, до карты организатора. Геометрия OSM показывает кандидатов, а не земельные права или проверенные коммуникации.
- Расценки демонстрационные; итог не является коммерческим предложением.
- Приживаемость — экспертные правила, без полевой калибровки. ROC-AUC не измерялась.
- Среднее взвешено по количеству растений: первый год — все виды, второй и третий — только многолетние (`plan.ts:305–312`). Нули у однолетников после первого года отражают цикл модели, а не обследованные потери.
- Экоэффект — расчётная оценка, не измерение. Показатели т/год даны на горизонте 5/10/20 лет; не складывать их как накопленный объём.
- Нет коэффициента пыли и данных о населении. Деградация без карты состояния не выявляется: 0 в исходном счётчике не доказывает отсутствие проблемы.
- Категории проблем пересекаются. Дорожная карта — жадная эвристика, не математический оптимум.

## Файлы и проведённые проверки

### PDF отчёта

ReportLab, шрифт Arial с кириллицей. Четыре страницы: зона/смета/подбор; посадка/приживаемость; уход/эффект; город/источники. Все страницы отрендерены Poppler и осмотрены. Исправлено отсутствие глифа нижнего индекса: в PDF используются CO2/O2. Проверены извлекаемый текст, количество страниц и сумма статей. Это внешний отчёт на данных генератора, не доказательство браузерного экспорта.

### Excel

Авторинг через bundled Artifact Tool. Четыре листа: «Отчёт», «Посадка», «Уход», «Город». Все листы отрендерены и осмотрены; формулы пересчитаны; ошибок формул не найдено. Временное увеличение статьи на 100 ₸ изменило общий итог на 100 ₸, затем исходное значение восстановлено. Сохранённый XLSX повторно проверен как ZIP/XML: 7 формул и их числовые кэши корректны. Аналитические прогнозы зафиксированы как снимок; книга пересчитывает суммы, а не всю модель `analyzeZone`. Microsoft Excel не запускался.

### Презентация

10 слайдов, 16:9, Arial; четыре редактируемые таблицы и редактируемая архитектурная схема. Проверка упаковки PPTX, геометрии, шрифтов и повторный импорт Artifact Tool прошли без замечаний. Каждый слайд отрендерен и осмотрен. PowerPoint не запускался.

Нативный PDF-export Artifact Tool в bundled runtime завершился ошибкой `Cannot find module '#standard-fonts/Helvetica'`. PDF презентации собран из успешно отрендеренных PNG тех же десяти слайдов. Он содержит растровые страницы; редактируемый оригинал — PPTX. PDF отчёта содержит обычный текст и таблицы.

## Граница доказательств

Файлы защиты подтверждают согласованность демонстрационных чисел и пригодность материалов для просмотра. Они не подтверждают кнопки экспорта приложения, единый mock-поток координатор→работник, роли/CSRF на сервере или полный браузерный E2E. Прямые API-прогоны и браузерные проверки отмечаются отдельно в `acceptance-checklist.md` и `coordination/qa.md`.
