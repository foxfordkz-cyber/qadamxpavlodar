## Подготовка до запуска секундомера

1. Записать `git rev-parse HEAD`, режим, адрес сервера, дату смены UTC+5 и результат ручного прогона ниже. На экране назвать «Сервер API» либо «Тестовый источник». Выбрать смену, где действительно есть учебное задание: текущая дата компьютера не гарантирует наличия задач.
2. На машине с Docker из корня репозитория выполнить:

   ```bash
   docker compose up --build
   ```

   Открыть `http://localhost:8080/?source=api#/map`; запасной режим — `http://localhost:8080/?source=mock#/map`. Compose поднимает nginx и сервер Node/SQLite; база и фото сохраняются в томе `gp-data`. PR #12 разрешает серверу слушать `0.0.0.0` в контейнере. **В среде подготовки Docker CLI/Engine отсутствует: запуск контейнеров здесь не подтверждён.** Для локального запуска без Docker использовать README; стандартный адрес разработки — `http://localhost:5173/?source=api`, API — порт 3100.
3. Подготовить `coordinator`, `foreman1`, `worker1`. Пароль хранится в игнорируемом `apps/server/.env`; без него сервер при первом старте печатает сгенерированный пароль в `docker compose logs server`. Не включать пароль, cookie или токены в снимки и отчёты.
4. Для показа модели настроить `apps/server/.env` по `apps/server/env-templates/groq-gemini.env`: Groq — `LLM_*`, Gemini — `LLM2_*`, хосты — `LLM_ALLOWED_HOSTS`. Выполнить `npm --prefix apps/server run llm:check`, перезапустить сервер и проверить ответ с отметкой модели, расчётами и источниками. При лимите, ошибке или тайм-ауте основной модели код пробует резерв; если модели недоступны, отвечает по правилам. UI показывает метод и причину переключения. **В этом прогоне реальные вызовы Groq/Gemini и переключение резерва не проверены.** В mock ассистент работает по правилам.
5. Специалисту заранее отрепетировать поиск «Торайгырова 1/5» или другого найденного адреса. Поиск использует снимок OSM центра Павлодара, поддерживает русские и казахские названия, но не покрывает весь город. Для рисования выбрать место внутри района карты: минимум три вершины, площадь больше 50 м², без самопересечения. После «Сохранить зону» проверить карточку и площадь. Сохранение доступно специалисту.
6. Для сравнения с подготовленным отчётом открыть `site-osm-1569993037` («Газон у улица Толстого»). Генератор читал raw OSM fixture с `waterAvailability.value=null`, live mock seed задавал 70. В первой репетиции стоимость отчёта — **10 839 718 ₸**, live mock — **10 831 618 ₸**; разница **8 100 ₸** связана с разными входами. Это исторические значения. Для точной сверки текущего экрана выровнять снимок и параметры либо открыть отчёт того же UI.
7. Подготовить проверенные PDF/XLSX пакета и fixtures импорта. Генераторные файлы — отдельные артефакты; кнопки приложения требуют своей проверки. Текущий экспорт «Excel (.xls)» сохраняет HTML-таблицы, PDF получается через печать браузера. Проверить резервную подложку заранее: mock не требует API, но карты, изображения и холодная загрузка могут зависеть от сети.
8. В «Приживаемости» теперь показать модель и сравнение с правилами. Прогноз первого года — логистическая регрессия, обученная на 9 600 строках из 12 000 синтетических примеров; годы 2/3 сохраняют экспертное затухание. Документированные ROC-AUC 0,7324 и Brier 0,1772 получены на 2 400 синтетических проверочных строках. Это разработческая валидация генератора, не точность на данных Павлодара; литературного CSV сейчас нет. Диапазон отражает групповую ошибку калибровки, а не гарантированный индивидуальный 95%-й интервал. Подготовленные PDF/XLSX и видео первой репетиции модель PR #8 не демонстрируют.
9. В «Уходе» доступно предложение черновиков заданий на следующие 1–12 полных месяцев UTC+5. Оно использует зарегистрированные растения внутри зоны; без растений предлагает осмотры участка. Создавать задания может только специалист, строки сохраняются отдельно. Полив/прополка адресованы растениям; бюджет без расценок даёт предупреждение, а не смету. Для mock-показа полива использовать `site-osm-1490224716`, три явно помеченных демо-растения и горизонт 12 месяцев. В API эти mock-растения автоматически не появляются. Перед повторным выпуском после перезагрузки проверить список заданий; этот UI-сценарий в текущем прогоне не проверен.

## Исторические проверки и резервное видео

Первая проверка до merge актуальной `codex/coordinator` использовала сервер `1fa8e2f`: прямые API-цепочки обследования и посадки прошли; посадка создала 2 растения и 2 черновика ухода. Worker UI отправил и исправил фотоотчёт, но создание задания, возврат и приёмка были выполнены API-запросами. Это **HYBRID**. Старые сбои координатора в маршрутах, CSRF и отображении фото нельзя объявлять активными на новой сборке без воспроизведения.

`mock-demo-full.webm` — **9:50.60, 1440×900, 25 fps, VP8, без аудио**. Запись содержит 52 основных сегмента и приложение с результатом CSV; зафиксированы 0 ошибок действий и 0 ошибок страницы. Полное офлайн-воспроизведение завершилось без ошибки; проверены 14 контрольных кадров. Видео записано до обновления сценария под PR #5/#6/#7/#8/#12 и не доказывает работу новых возможностей.

В видео показаны основное mock-приложение и отдельный `tools/worker-demo` с циклом `GP-PLANT`: старт, фото, вклад, итог 2 дерева и 4 кустарника, возврат через тестовую панель, исправление и приёмка. У стендов разные состояния. Его 2 загрузки, 2 вклада, 2 отчёта и 6 учебных растений не следует смешивать с 2 растениями исторического прямого API-прогона.

Частичная запись `mock-demo-partial.webm` на 3:30.96 остаётся дополнительным материалом. Холодный запуск всего приложения без сети не подтверждён. Подробности — [video-storyboard.md](video-storyboard.md), `defense/video-notes.md` и [acceptance-checklist.md](acceptance-checklist.md) в пакете.
