2. Основной показ готовить на `http://localhost:5173/?source=mock#/map`. На экране и голосом назвать режим. В браузере с API показывать подтверждённые действия с точным обозначением границ проверки; полный сценарий считать принятым только после прогона той же сборки. Переключатель режима сам по себе не доказывает работу сервера.
3. Для связи с отчётом использовать зону `site-osm-1569993037` («Газон у улица Толстого»). **Одинаковый ID не означает одинаковые входы:** генератор читает raw OSM fixture с `waterAvailability.value=null`, а live mock seed задаёт 70. В зафиксированном сравнении стоимость отчёта — **10 839 718 ₸**, live mock — **10 831 618 ₸**; разница **8 100 ₸** связана с различием входных данных. Не обещать точное равенство с экраном; для строгой сверки сначала выровнять snapshot и параметры либо открыть отчёт текущего UI.
4. Отдельно открыть «Проблемные зоны», «Приоритеты» и отчёт этой зоны. Подготовить корректный и ошибочный файл импорта только при наличии проверенных fixtures. Не загружать случайные файлы на сцене.
5. Подготовить проверенные PDF и Excel из пакета защиты. Они демонстрируют данные генератора; отдельно проверить кнопки экспорта приложения. Текущий код кнопки Excel сохраняет HTML-таблицы с расширением `.xls`, а не нативный `.xlsx` (`ReportPage.tsx:27–29`).
6. Проверить карту при отключённой сети заранее: mock не требует сервер API, но подложка, фотографии и холодная загрузка могут зависеть от сети. Полностью автономный запуск всей системы пока не подтверждён.
7. Для модуля работ иметь отдельный учебный снимок, проверенный маршрут и назначение. В базовом `18c2541` маршрут `#/worker` отсутствует; QA подтвердил его после локальной интеграции. Foreman1 назначил worker1 и начал работу; worker1 загрузил синтетическое фото, отправил и исправил отчёт через UI. Задание, возврат и приёмка выполнены прямым API: это **HYBRID**, не полный браузерный E2E. Финальный UI показывает «Работа подтверждена». Смена даты, выход и отображение ролей повторно проверены без прежних ошибок. При использовании `tools/worker-demo` назвать его отдельным стендом.
8. Отдельно записан полный UI-цикл `GP-PLANT` в standalone `tools/worker-demo`: назначение Алии и Ерлана → старт → синтетическое фото и подтверждённый разбор → вклад → итог 2 дерева и 4 кустарника → возврат через тестовую панель координатора → новое фото/исправление → повторный итог → приёмка. Результат стенда: 2 загрузки, 2 вклада, 2 отчёта, 6 учебных растений. Это независимое свидетельство mock-компонента; единый main coordinator → worker сценарий этим не подтверждён.
