## Два сценария и три режима

| Режим | Когда использовать | Что можно утверждать |
|---|---|---|
| A — основной, облачный API | Только после реальной публикации и выполнения [облачной приёмки](acceptance-checklist.md#облачная-приёмка) | Проверенный публичный веб работает с удалённым сервером, общей БД и фото. URL, web/server SHA и источник фиксируются в manifest |
| B — резерв, локальный API | Подготовленный и отдельно проверенный локальный web/server на компьютере защиты | Это серверное сохранение в локальной БД. Оно не доказывает облачный доступ |
| M — независимое mock-демо, отдельный вариант резерва B | При недоступности API или для явно учебных расчётов | Это данные браузера. Нет подтверждения общего серверного хранения или передачи одного задания из основного mock в worker-demo |

## Переход на резерв и проверка сбоев

До выхода к жюри выполнить отдельную репетицию B и M. Если облако не принято, основным фактическим показом становится проверенный резерв с его точной подписью. Если подключение не готово к сцене, кратко сказать: «Сейчас сервер недоступен; продолжаем на локальном API» либо «Показываем независимое учебное демо». Не выдавать снимок облачной БД и локальную БД за один процесс.

Проверку холодного старта, 503/сети, отмены ожидания и восстановления выполнить вне пятиминутной речи. Повторы проверки доступности — только чтение; фото/отчёты автоматически не переотправляются. При неопределённом результате отправки сохранить черновик и ключ, восстановить связь, повторить вручную и проверить отсутствие дубликатов на сервере. Локальные тесты этого поведения не заменяют реальный облачный прогон.

Общий SHA подтверждает Дамир, адрес и данные API — Бекзат, кадры и независимую проверку — Айдана, речь и резерв — Танирберди. Слайды/полный ролик ещё не созданы для этого сценария. Публикация финального облачного API и общая приёмка остаются pending до доказательств в чек-листе; опубликованный mock учитывается отдельно.
