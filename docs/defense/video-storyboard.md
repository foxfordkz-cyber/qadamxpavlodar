## Границы доказательств и резерв

1. Монтаж фиксирует реальные состояния. Он не является непрерывным скринкастом и не заменяет журнал ручного прогона. Подготовка учебных задач через CLI отделена от действий пользователя в UI.
2. API и mock подписаны. Mock-карта и mock-кабинет используют разные хранилища; API-кабинет на видео работает с отдельной учебной БД.
3. Ввод казахского текста не равен успешному ответу. После доработки нужен повтор точно того же вопроса и проверка содержания; до этого многоязычность не отмечается PASS.
4. Если модель на живой защите не отвечает за **8 секунд**, показать готовую очередь на 50 млн; не повторять запросы на сцене. Это лимит выступления, не серверный timeout. Для уже выявленной смысловой ошибки назвать ошибку, а не отсутствие ответа.
5. Для машины времени запасной ход — таблица эффекта 5/10/20 лет. Для шторки и кабинета — соответствующие проверенные композиции этого файла. При переходе с живого UI на монтаж назвать его.
6. Alt+P скрывает служебную строку источника, поэтому подписи API/mock сохранены в композициях. Он не включает fullscreen и не меняет стили внутри shadow DOM кабинета.
7. Метрики приживаемости относятся к синтетике; CO₂/охлаждение — прогноз. Реальные камера/GPS, физический телефон, Docker и холодный офлайн-запуск этим видео не подтверждаются.

С [scenario.md](scenario.md) сверены фактические эпизоды и интервалы. Живой план занимает 8:30 плюс 0:30 резерва; устная репетиция с секундомером **не выполнена**. Ролик можно использовать вместо соответствующих частей показа, а не добавлять поверх девяти минут.
