## Быстрый запуск

1. Сначала открыть URL выбранного режима и назвать его зрителям: «облачное DEMO» либо «учебный mock». Значок подключения mock не доказывает работу сервера.
2. Для облака использовать только согласованные DEMO-учётные записи, переданные приватно. В памятке, QR и архиве паролей нет. При отсутствии доступа выбрать M; не показывать учебную роль как вход в реальный API.
3. В M главный экран открывается без обязательного входа. Для кабинета выбрать учебную роль через «Режим проверки». После полной перезагрузки mock роль сбрасывается на координатора, а язык сохраняется: снова выбрать «Работник» или «Бригадир»; сохранение mock-сессии не обещается. Основная карта и worker demo имеют отдельные учебные хранилища.
4. Перед речью открыть существующий участок, расчёт и заранее проверенные RU/KK Word. Конкретные параметры и числа — в [сценарии](scenario.md#подготовка-до-секундомера). Не переносить сумму mock на другое облачное задание.
5. Кабинет показывать на 1280 и 375 CSS px. Опубликованные c970264/84d009e содержат RU/KK; результат публичной проверки кабинета записывается отдельно от локальных проверок. В старых видео a66d542 и portable fdc6e75 остаётся прежнее поведение языка.

## Что говорить о границах

В облаке поиск/geocode, новые и нарисованные зоны, GIS-импорт, календарь и ассистент пока ограничены ответами 503. Команды «нарисуй зону» / «аймақ сыз» и ответы ассистента показываются только в явно названном mock. Ошибка API не подменяется данными mock.

Модель обучена на синтетических примерах; прогноз оценочный, не гарантия приживаемости. Демо-осмотры не являются полевым подтверждением. Сравнивать «Прогноз и факт» можно только для сопоставимых партии и горизонта; неизвестное состояние не считать гибелью.

## Дальнейшие действия без изменения публикации

Обе публикации завершены в согласованное окно. Айдана может проверять зафиксированные версии; авторизованный cloud-проход требует приватных согласованных DEMO-доступов. До окончания приёмки не загружать эти или другие архивы повторно. При критическом дефекте сначала согласовать отдельное окно или откат с Айданой и капитаном. Не создавать третий проект и не менять Render ради frontend.

Полная передача и последующие результаты read-only/UI-проверок — в [журнале публикации](../cloud-publication-handoff-2026-11-01.md). Проверки с авторизацией остаются NOT RUN без согласованного приватного DEMO-доступа. Пароли, ключи и исходные приватные отчёты не включать в публичную передачу.
