## Что должно предоставить подключение

`features/coordinator/outcomes/model.ts` описывает **входные props компонентов, не HTTP DTO**.
`OutcomesPanel` принимает необязательную стабильную функцию `load(signal)` и `requestKey`
для выбранной зоны/параметров. Конкретные методы адаптера и HTTP-маршруты здесь не определяются.

Адаптер должен передать:

1. `OutcomeVariant[]` из общих расчётов с настоящими provenance/версиями справочников.
2. `OutcomeCohort` с проверенными связями с существующим реестром и сохранённым целиком
   `OutcomeForecastSnapshot` либо `forecast: null`. Текущий расчёт не заменяет исходный.
3. Явно выбранный последний `OutcomeInspection` каждой партии либо `null`, с проверенными
   правами, принадлежностью и принятием источников. UI не объединяет состояния из разных осмотров.
4. Каталог видов и авторитетную календарную дату `asOf` от сервера (UTC+5).

После публикации адаптера: связать его с `load` в карточке зоны; проверить оба источника,
настоящий переход к доступному принятому отчёту, отсутствие/ошибку/повтор загрузки и смену
зоны. В компоненте есть отмена и игнорирование поздних ответов, но серверная проверка
прав и источников остаётся обязательной частью адаптера.

## Поведение интерфейса

- Ранжирование — только `compareOutcomeVariants`. Равные минимумы допускаются; неполные,
  смешанные и несовместимые варианты не становятся победителями.
- Посадка раскрыта по готовым статьям material/prep/work; уход и резерв отдельно.
  Отдельного придуманного subtotal или распределения смешанной сметы нет.
- `null` отображается как неизвестное значение с причиной и действием. Ноль остаётся нулём.
- Сводка и сопоставление осмотра — `summarizeOutcomeInspection` и `compareOutcomeForecast`.
  Месячный осмотр, отсутствие исходного прогноза и неполный охват не получают delta.
- Синтетическое обучение y1 и экспертное затухание y2/y3 указаны возле прогнозов.
  Демо-происхождение партии, прогноза и осмотра маркируется отдельно; демо-цены не превращают
  реальные наблюдения в демонстрационные.
- Ссылки отчётов используют существующий `#/reports?report=…`; произвольные URL не принимаются.
- ru/kk: 85 новых ключей; названия видов через `speciesName`. Карточки складываются на 375 px.

Браузер проверяет ранжирование, значения, переполнение, фокус клавиатуры, выбор партии,
сохранение выбора при смене языка, несопоставимый месячный осмотр, отсутствие прогноза,
loading/empty, имитированную ошибку 503 с успешным повтором, повреждённый вход, неполную
смету, частичный охват, отсутствие подключения и поздний ответ старого запроса.
Отказ 503 инъецируется в загрузчик; это **не проверка ответа существующего outcomes API**.

## Воспроизведение

В `apps/web`:

```powershell
npm ci
npm run typecheck
npm run build
npm run check:i18n
npm test
npm run dev -- --host 127.0.0.1 --port 5182 --strictPort
```

В другом терминале той же директории, после установки существующих зависимостей
`tools/e2e` и браузера Playwright:

```powershell
node scripts/check-outcomes-ui.mjs
```

По умолчанию скрипт использует `tools/e2e/node_modules/@playwright/test/index.mjs`.
`OUTCOMES_PLAYWRIGHT_PACKAGE` может указывать на уже установленный пакет другого
worktree; `OUTCOMES_UI_BASE` меняет локальный адрес, `OUTCOMES_UI_OUTPUT` — каталог
скриншотов/JSON (по умолчанию игнорируемый `dist-tests/outcomes-ui-browser`). Код E2E не меняется.

Изолированный экран: `/tests/fixtures/outcomes-ui.html?lang=ru` (или `kk`).
Сценарии через `case`: ready, loading, empty, retry, invalid, incomplete, partial,
unavailable, race. Эти файлы не входят в production bundle и не связаны с mock API.
