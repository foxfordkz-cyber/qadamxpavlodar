# Кабинеты работника и бригадира · V2

Интеграция участника 4, ветка `worker/real-server`. Основа — `codex/coordinator` (18c2541).
Кабинет доступен в общем приложении на `#/worker`; роли бригадира и работника перенаправляются на него после входа. В режиме `?source=api` используется настоящий сервер, в mock — учебный источник кабинета.

## Запуск демо

Из корня репозитория (Node.js 20+, без установки дополнительных зависимостей):

```sh
npm --prefix tools/worker-demo run dev
```

Открыть http://127.0.0.1:4173. В Windows также можно запустить `tools/worker-demo/START-WORKER.cmd`.
Остановка — Ctrl+C. Проверки: `npm --prefix tools/worker-demo test`.

## Возможности

- Смена и карточка задания, начало после ответа источника, фото, заметка, сообщение о проблеме.
- Назначение исполнителей бригадиром с проверкой состава, навыков, времени и ресурсов на тестовом источнике.
- Материалы работников в общем черновике, итог бригадира, возврат координатором и исправление.
- Плановые и фактические количества, исполнители, согласованная версия проекта и синтетическая схема.
- Локальные черновики IndexedDB, повтор с тем же ключом, явное разрешение конфликта версии.
- Разбор заметки с подтверждением человеком; в демо — правила, без настоящей модели.

## Границы готовности

Маршрут интегрирован из `feature/worker-route`. Тела запросов сверены с `server/srv-03-06` (1fa8e2f); сама серверная ветка в этот коммит не объединяется. До её слияния сервер можно запускать из отдельного Git worktree, задав web-процессу `VITE_API_PROXY=http://127.0.0.1:3100`.
Mock кабинета и mock координатора используют разные учебные хранилища: переход между ними не доказывает сквозной серверный процесс.
Данные — синтетические: две бригады, восемь задач, две позиции каталога, смена 28.10.2026 UTC+5.
Модуль бригад дополняет основной сценарий анализа участка, подбора, сметы, ухода и эффекта из общего README.

Автоматические проверки включают локальную логику и контрактные регрессии форм, CSRF, версий, пагинации, ревизий проектов и идемпотентности. Запуск: `npm --prefix tools/worker-demo test`. Сборка: `npm --prefix apps/web run build`; предупреждение о крупных JS-чанках сохраняется.
Полный браузерный сценарий дополнительно зависит от интеграции координаторского v2compat/transport, которую ведёт Дамир. Мобильная приёмка и проверка казахского перевода носителем остаются отдельными этапами.
Тексты защиты относятся к модулю работ; перед выступлением нужно согласовать их с общим продуктом и официальным регламентом.
