ОГРАНИЧЕНИЯ И ИСПРАВЛЕНИЯ V2

ИСПРАВЛЕНО В ХОДЕ РАБОТЫ
1. Начальная модель без общего контракта заменена адаптером V2: статусы, роли, version, expectedVersion, Idempotency-Key, ObservationDraft.
2. Возврат отчёта теперь требует assigned -> in_progress перед новым итогом. Раньше шаблон разрешал прямую отправку исправления.
3. Добавлены отдельные материалы работников и общий итог бригадира. Материалы не переводят задачу в submitted.
4. Добавлены минимум состава, навыки, доступность, общий ресурс, запрет чужого участника и замены начатого назначения.
5. Неполная посадка не проходит приёмку. Повтор принятия не создаёт второй набор учебных растений.
6. Добавлен явный разбор 409. Неопределённый сетевой исход повторяется прежним ключом и payload.
7. Асинхронное чтение старой сессии не показывает задание новому пользователю. Локальные черновики разделены по scope и ID.
8. Ошибка IndexedDB больше не сопровождается безусловной надписью об успешном локальном сохранении.
9. Убрана неверно унаследованная инструкция полива из заданий осмотра. Основной demo V2 — осенний осмотр и синтетическая посадка, без придуманных сезонных норм.
10. Пустое фото, подмена типа, слишком большой файл, отказ загрузки обрабатываются отдельно.
11. Предпросмотр static server читает файл до отправки HTTP 200, отсутствующий файл получает 404.
12. Встраиваемый режим скрывает отдельную шапку/боковую панель, чтобы использовать общую оболочку команды.
13. История итогового отчёта показывает плановые/фактические количества и состав исполнителей; отсутствие фактического количества не подменяется нулём.

Согласование недоопределённых тел запросов в docs/worker/integration.txt.

При отсутствии CarePolicy тестовая приёмка не придумывает следующие нормы ухода и не помечает растения здоровыми.

ОГРАНИЧЕНИЯ ДЕМО
Test transport находится в браузере. Его данные доступны через инструменты разработчика: нельзя использовать реальные персональные сведения.
Метаданные демо сохраняются в одном localStorage namespace. Большие/множественные фото могут превысить квоту. Предпросмотр фотографий сохраняется только до 600 КБ на файл, остальные имеют метаданные.
Для production требуется файловое хранилище сервера. Тестовый источник не заменяет атомарные транзакции и контроль доступа.
Одна активная вкладка. При параллельной работе вкладок нужно перезагрузить состояние; полноценная межвкладочная блокировка не заявлена.
Нет service worker, общего офлайн-кэша, маршрутизации по улицам и фонового GPS.
Часовой пояс UTC+5; UTC-значения и клиентские сведения сохраняются отдельно по происхождению.
