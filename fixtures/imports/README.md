# Проверка Shapefile-импорта

## Независимые файлы с открытой лицензией

Два архива Natural Earth **5.0.0** скачаны без изменений 30.10.2026.
[Описание слоёв](https://www.naturalearthdata.com/downloads/110m-physical-vectors/),
[условия использования](https://www.naturalearthdata.com/about/terms-of-use/): public domain.
Это мировые географические объекты, **не данные об озеленении Павлодара**. Архивы
нужны только для проверки формата и не входят в seed/mock городских данных.

| Файл и проверенная ссылка загрузки | Размер | SHA-256 |
|---|---:|---|
| [ne_110m_geography_regions_elevation_points.zip](https://naturalearth.s3.amazonaws.com/110m_physical/ne_110m_geography_regions_elevation_points.zip) | 16 509 байт | `5f1952dc9b8b947fe492778282a67c7ecd84c66052977f1400f3e6b817f30b61` |
| [ne_110m_lakes.zip](https://naturalearth.s3.amazonaws.com/110m_physical/ne_110m_lakes.zip) | 23 622 байта | `f2eed3c738a93010770acb0ba44273ea6a83b053641588bc902d9d6fd1cdafcb` |

Первый архив содержит 19 точек WGS 84: через файловое поле браузера все проходят
предпросмотр и отдельное подтверждение, записываются в SQLite. Предупреждения о
координатах вне Павлодара и пропущенных названиях требуют подтверждения. DBF-названия,
идентификаторы и координаты сверяются с manifest, прочитанным **PyShp**, независимо
от используемого сервером **shpjs**. Запись делается только в изолированный тестовый
слой `city` с пометкой demo, не в пользовательскую БД.

Второй архив содержит 24 полигона. У 14 есть последовательные повторы замыкающей
вершины — это подтверждает и независимое чтение исходного SHP. Текущий валидатор
отклоняет эти геометрии: 10 допустимых / 14 с ошибкой, сохранение **всего** слоя
блокируется даже после подтверждения предупреждений. Архив не исправляется на лету,
проверки не ослабляются. Это зафиксированное ограничение совместимости, не успешный
импорт всех файлов Natural Earth. Для демонстрации пригодных полигонов есть отдельный
синтетический fixture ниже. Муниципальный SHP и проекции, отличные от WGS 84, не проверены.

`inspect-natural-earth.py` только читает архивы, сверяет SHA-256 и создаёт
`*.expected.json`; файлы SHP/DBF не переписывает. Для повторного чтения установите
PyShp 3.1.6 и запустите скрипт с этой библиотекой в `PYTHONPATH`.

## Синтетические полигоны для проверки UTF-8

`synthetic-zones.zip` — настоящий двоичный ESRI Shapefile, созданный независимой библиотекой [PyShp 3.1.6](https://github.com/GeospatialPython/pyshp). Внутри: `zones.shp`, `.shx`, `.dbf`, `.prj`, `.cpg`. Два полигона, координаты WGS 84 / EPSG:4326, UTF-8 названия с русскими и казахскими буквами.

**Геометрии выдуманы для теста. Это не городской реестр и не рекомендация по посадке.** Во время проверки слой сохраняется с `dataClass: demo` только в отдельную временную SQLite. Ожидаемые названия и координаты находятся в `synthetic-zones.expected.json`.

## Повторить браузерную проверку

Нужны Node 24, зависимости `apps/web` и `apps/server`, установленный Playwright из `tools/e2e` и Chromium. Из корня репозитория:

```sh
npm --prefix apps/web ci
npm --prefix apps/server ci
npm --prefix tools/e2e ci
cd tools/e2e
npx playwright install chromium
cd ../../apps/server
node --import tsx scripts/check-shp-import.mts
```

Если Playwright уже установлен в другом worktree, можно передать абсолютный путь к его `tools/e2e/package.json` через `PLAYWRIGHT_PACKAGE_JSON`, не переустанавливая его.

Скрипт создаёт отдельную БД и временный пароль в памяти, поднимает API на случайном локальном порту и frontend на `127.0.0.1:5187`. Этот порт должен быть свободен. Пользовательские `.env`, БД и серверы не используются. Созданные скриптом процессы и временная БД удаляются при завершении.

Проверяются RU/KK, 1280/375 px, mock/API:

- Двоичный ZIP проходит через файловое поле, браузерный кодировщик и настоящие HTTP endpoints. Предпросмотр не сохраняет объекты; отдельное подтверждение сохраняет два полигона и их названия. Повторное чтение после перезагрузки возвращает сохранённые зоны.
- Независимые неизменённые архивы: 19 реальных географических точек проходят импорт; архив из 24 полигонов с повторными вершинами корректно блокируется. Данные сохраняются только во временный тестовый слой.
- Архив без `.prj` и повреждённый ZIP возвращают ошибки API; ошибка не заменяется данными mock и не меняет ранее сохранённый слой.
- Mock предлагает GeoJSON/KML/CSV, честно отклоняет принудительно выбранный SHP ZIP и сохраняет работу CSV-предпросмотра без запросов импорта к API.
- Нет ошибок страницы и горизонтального переполнения. Скриншоты и JSON результатов записываются в игнорируемую папку `apps/web/dist-tests/shp-import`.

Это отдельная проверка импорта, не полный E2E приложения. В GitHub Actions она не включена. Проекции, отличные от EPSG:4326, этим fixture не проверяются.

Проверено 30.10.2026 поверх `b53c180`: браузер **8/8** (mock/API × RU/KK × 375/1280),
web **124/124**, server **65/65**, worker **79/79**, typecheck/build и все `check:*`
PASS, i18n **1582/1582**. Серверные тесты: `npm test -- --test-concurrency=2`.
Сборка сохраняет предупреждение чанков >500 kB. Docker, публичный deploy и полный
E2E приложения не запускались. Новые казахские пояснения требуют вычитки Бекзатом.

## Пересоздать fixture

Python/PyShp нужны только автору fixture, они не являются зависимостями приложения или обычных тестов:

```sh
python -m pip install --target apps/web/dist-scripts/pydeps pyshp==3.1.6
python fixtures/imports/make-shp-fixture.py apps/web/dist-scripts/pydeps
```

Генератор фиксирует дату DBF и ZIP и не скачивает городские данные. Обычный `npm test` в `apps/web` читает уже сохранённый архив и проверяет сохранность байтов, кодирование, лимит размера и сообщения в RU/KK.
